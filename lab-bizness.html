Bizness

Cuando hacemos el escaneo con nmap podemos ver los puertos 80, 22 y 443 abiertos. Si ingresamos a la página web, automáticamente nos encontramos con virtual hosting el cual tendremos que contemplar en nuestro archivo /etc/hosts.

Una vez hecho el paso anterior , la página web nos redirecciona a https, así que podemos ver que nos redirecciona a https del puerto 443.

En la página web no encontramos nada interesante y comenzamos con el fuzzing.

Fuzzing

En el fuzzing vemos muchas redirecciones 302 por lo que con el parámetro -L en wfuzz seguimos las redirecciones y podemos ver algo interesante al cabo de un rato: un directorio content.

Si nos vamos al directorio content nos lleva directamente a un panel de login administrativo de un software llamado OFbiz.

Investigando un poco podemos ver que este software se utiliza en entornos empresariales para centralizar y automatizar según que procesos dentro de un negocio.

Authentication Bypass

Buscando por google primero si podemos acceder con las credenciales por defecto, podemos ver que no tenemos manera.

Así que esta vez me centro en la búsqueda de exploits. Encuentro un bypass de la autenticación para unas versiones en concreto.

Yo aún no se que versión de este software es por lo que probamos el exploit. En el poc nos comentan que hay una ruta vulnerable que supuestamente puede llegar a crear un usuario y devolvernos un imput.

Con el exploit nos damos cuenta de que esta vulnerabilidad se acontece y que podemos inyectar comandos.

Nos establecemos una reverse shell y estamos dentro.

Escalada de privilegios

Después de haber revisado los sudoers, privilegios SUID y SGID, capabilities, ficheros o directorios ocultos en el escritorio, desactualización del kernel etc descargué el leanpeas para hacer una enumeración completa del sistema.

Tras terminar la enumeración y revisar el output, llego a una parte donde leanpeas me descubre archivos de una base de datos llamada derby.

Acudiendo a las rutas de esta base de datos nos damos cuenta de que hay decenas de archivos con información. Sin saber que buscar me dedico a buscar información y me doy cuenta de que esta base de datos almacena contraseñas con la encriptación SHA por lo que buscaré eso a partir de ahora.

Con el siguiente comando busco en todos los archivos a la vez: cat * | grep SHA y encuentro una línea dentro de un archivo donde podemos ver una contraseña hasheada con SHA1 y salty.
